# ABI

[English](./README.md) | [简体中文](./README.zh-CN.md)

ABI is an AI-driven business intelligence platform for building data sources,
datasets, reports, interactive BI pages, sharing workflows, tenant management,
and AI-assisted analysis in one extensible system.

The project is maintained by Usoft as an open source product and is released
under the [Apache License 2.0](./LICENSE).

## Features

- Multi-tenant system management, including users, roles, permissions, tenants,
  dictionaries, system configuration, file upload, and tenant site settings.
- Security modules for password login, client authentication, JWT-based access,
  third-party authentication, and CAS integration.
- BI management for data sources, datasets, applications, pages, page templates,
  reports, sharing, and authorization scopes.
- AI capabilities for model configuration, conversations, skill import, SQL
  generation, page assistance, and report interpretation.
- Multi-database initialization scripts for MySQL, PostgreSQL, H2, Oracle, and
  SQL Server.
- React-based management console and BI design/runtime UI.

## Architecture

The repository is organized as a Maven multi-module backend with a separate
React frontend:

| Path | Description |
| --- | --- |
| `usoft-common` | Common API models, exceptions, utilities, SSE support, and shared helpers. |
| `usoft-core` | Core Spring infrastructure, MyBatis helpers, tenant support, security context helpers, and global exception handling. |
| `usoft-security*` | Authentication, authorization, JWT, third-party login, and CAS support. |
| `usoft-system*` | System administration APIs and services for users, roles, tenants, permissions, files, icons, and configuration. |
| `usoft-ai*` | AI model, conversation, skill, prompt, and agent integration modules. |
| `usoft-bi*` | BI data source, dataset, page, report, share, and authorization modules. |
| `usoft-launcher` | Spring Boot application entry point and runtime configuration. |
| `webapp/packages/bi-react` | React frontend built with Rsbuild. |
| `assembly` | Runtime packaging scripts, Docker resources, and binary assembly descriptors. |

## Requirements

- Java 21
- Maven 3.9 or later
- Node.js 22
- npm 10
- A supported database when running outside the in-memory H2 profile

Before building the backend, confirm that Maven is using Java 21:

```bash
java -version
mvn -v
```

## Backend

The backend entry point is `usoft-launcher`.

### Configuration

The default server port is `8080`, and the backend context path is
`/jgsz-api`.

The active database profile is controlled by `DB_TYPE`:

| `DB_TYPE` | Profile file |
| --- | --- |
| `mysql` | `application-mysql.yml` |
| `pgsql` | `application-pgsql.yml` |
| `h2` | `application-h2.yml` |
| `oracle` | `application-oracle.yml` |
| `sqlserver` | `application-sqlserver.yml` |

Common environment variables:

| Variable | Description |
| --- | --- |
| `DB_TYPE` | Database profile. Defaults to `mysql`. |
| `JWT_SECRET` | JWT signing secret. Required for normal authentication. |
| `JWT_TTL_SECONDS` | JWT lifetime in seconds. Defaults to `3600`. |
| `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE` | MySQL connection settings. |
| `MYSQL_USERNAME`, `MYSQL_PASSWORD` | MySQL credentials. Development defaults are present in configuration. |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, `REDIS_DATABASE` | Redis connection settings. |
| `OPENAI_API_BASE_URL`, `OPENAI_API_KEY` | OpenAI-compatible model provider settings. |
| `OPENAI_DEFAULT_MODEL`, `OPENAI_CODE_MODEL`, `OPENAI_EMBEDDING_MODEL` | Default model names. |
| `DASHSCOPE_API_BASE_URL`, `DASHSCOPE_API_KEY`, `DASHSCOPE_CODE_MODEL` | DashScope model provider settings. |
| `SM2_PRIVATE_KEY` | SM2 private key used for password decryption. |
| `BI_CHAT_FILE_DB_PATH` | Local path for cached BI chat file databases. |
| `FILE_STORAGE_PATH`, `FILE_VISIT_PATH_PREFIX` | Upload storage and public visit path settings. |

### Run Locally

For a lightweight local run, use the H2 profile:

```bash
export DB_TYPE=h2
export JWT_SECRET=change-this-local-secret
export OPENAI_API_KEY=your-openai-compatible-api-key

mvn -pl usoft-launcher -am spring-boot:run
```

For MySQL, prepare a local database and run:

```bash
export DB_TYPE=mysql
export MYSQL_HOST=localhost
export MYSQL_PORT=3306
export MYSQL_DATABASE=bi
export MYSQL_USERNAME=your-database-user
export MYSQL_PASSWORD=your-database-password
export JWT_SECRET=change-this-local-secret
export OPENAI_API_KEY=your-openai-compatible-api-key

mvn -pl usoft-launcher -am spring-boot:run
```

The database schema and initial data are loaded from
`usoft-launcher/src/main/resources/db`.

### Build

```bash
mvn -DskipTests package
```

The launcher assembly is generated by the `usoft-launcher` module.

## Frontend

The frontend lives in `webapp/packages/bi-react`.

### Configuration

Frontend runtime behavior is controlled through public environment variables:

| Variable | Description |
| --- | --- |
| `PUBLIC_BASE_PATH` | Frontend base path. Defaults to `/webapp`. |
| `PUBLIC_API_URL` | API base path used by the frontend. Defaults to `/api`. |
| `PUBLIC_SM2_PUBLIC_KEY` | SM2 public key used before submitting passwords. |
| `PUBLIC_REGISTER_ENABLED` | Enables registration UI when set to `true`. |
| `PUBLIC_FORGOT_PASSWORD_ENABLED` | Enables forgot-password UI when set to `true`. |
| `PUBLIC_SSO_THIRD_ENABLED` | Enables third-party SSO UI when set to `true`. |
| `PUBLIC_SSO_CAS_ENABLED` | Enables CAS SSO UI when set to `true`. |
| `PUBLIC_SSO_WECHAT_OPEN_ENABLED` | Enables WeChat Open SSO UI when set to `true`. |
| `PUBLIC_SSO_DINGTALK_ENABLED` | Enables DingTalk SSO UI when set to `true`. |
| `PUBLIC_SSO_GITHUB_ENABLED` | Enables GitHub SSO UI when set to `true`. |

### Run Locally

```bash
cd webapp/packages/bi-react
npm ci
npm run dev
```

The development server proxies API requests to `http://localhost:8080` by
default. Set `PROXY_TARGET` to point to another backend instance.

### Build

```bash
cd webapp/packages/bi-react
npm ci
npm run build
```

The build output is generated in `webapp/packages/bi-react/dist`.

## Production Notes

Some defaults are intentionally convenient for local development. They must be
reviewed before production deployment:

- Set a strong `JWT_SECRET`.
- Override `SM2_PRIVATE_KEY` and configure the matching frontend
  `PUBLIC_SM2_PUBLIC_KEY`; the built-in SM2 fallback is only for local
  development.
- Do not rely on default database credentials. The MySQL profile defaults to
  `root`/`root` for local development and must be overridden through
  environment variables in production.
- Review whether the H2 console should be available in the target environment;
  it is enabled by default for local development.
- Configure Redis, upload storage, public file access, model providers, and
  model API keys through environment variables or deployment secrets.
- Confirm that database initialization mode is appropriate for the deployment
  environment.
